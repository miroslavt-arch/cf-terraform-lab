# Topic 7 — Module design: thin interfaces, validation, version tags, outputs as contracts

**Concept in three sentences.** A module's variable surface is an API: keep it
one typed map with `optional()` defaults so every default is visible in one
place and call sites stay small. `validation` blocks turn your operational
rules into plan-time errors with messages you wrote, not API errors twenty
minutes into an apply. Outputs are the contract consumers pin against — and
they pin a **git tag**, not a branch, so upgrades are a reviewed diff.

## Files
- `infra/modules/zone-baseline/variables.tf` — the typed interface: one
  `map(object({...}))`, nested optional `metadata` object with `{}` default,
  four `validation` blocks
- `infra/modules/zone-baseline/outputs.tf` — the contract (`zone_ids`,
  `record_fqdns`, `settings_applied`)
- `infra/modules/zone-baseline/README.md` — generated by terraform-docs
  (pre-commit keeps it current)
- `infra/envs/lab/main.tf` — the consumer (pins `?ref=v0.1.0` once pushed)

## Steps

1. Run the demo:
   ```bash
   bash scripts/demo-07-validation.sh
   ```
2. Show version pinning (after the repo is public and tagged):
   ```bash
   git tag v0.1.0 8c4494d && git tag v0.2.0 bc277be && git push --tags
   # envs/lab/main.tf: source = "git::https://github.com/miroslavt-arch/cf-terraform-lab.git//infra/modules/zone-baseline?ref=v0.1.0"
   ```
3. Show the v0.1.0 → v0.2.0 upgrade as a diff (the added optional input):
   ```bash
   git diff v0.1.0 v0.2.0 -- infra/modules/zone-baseline/variables.tf
   ```

## Expected output (REAL, captured 2026-08-14)

Bad input (record key without `lab-` prefix) dies at plan:

```
Error: Invalid value for variable
Every DNS record key must start with 'lab-'. This module refuses to create
records that are not trivially identifiable as lab-owned (safety rule: build
only, never collide with pre-existing names).
```

Good input — the full unit suite:

```
Success! 5 passed, 0 failed.
real    0m0.424s
```

`git diff v0.1.0 v0.2.0` shows exactly one interface change: the
`manage_settings = optional(bool, true)` input (+ its gating in `main.tf`) —
optional, so v0.1.0 callers upgrade with a zero-change plan.

## Failure mode prevented
Interface sprawl (12 loose variables nobody dares remove), invalid input
reaching the API mid-apply, and "the module changed under me overnight"
(branch-tracking consumers).

## Reset
Nothing to reset — fully offline. `rm -rf tests/tmp-demo07` if a crashed run
left it behind.

## What to say
> "The error message you just saw was written by the module author, fired at
> plan time, in the caller's terminal. That's the difference between an
> interface and a pile of variables — and the tag pin means upgrades happen
> when the CONSUMER chooses, as a reviewable one-line diff."
